# 本轮优化与回归汇总

日期：2026-09-22。范围为既有项目的结构、计算/渲染效率、数据加载、页面生命周期和后台任务结果回写；不引入新的预测模型、评分规则或用户功能。

## 已完成

- 拆分命令行处理、预测器和验证模块，保留原入口、程序集和行为。
- 预测计算复用前缀统计及条件模型工作缓冲区。
- 走势图复用同内容刷新和完整重建中的文字单元格，避免重复创建；校验期号、日期、号码及历史遗漏变化，及时使缓存失效。
- 数据解析改为文本片段解析；保留字段、错误行和顺序规则。
- 组号先筛选候选再整理展示顺序，每次生成只汇总一次说明集合。
- 走势/历史页重载统一更新缓存，斜连渲染器不再重复订阅；记录、设置、组号、杀号、点位和票据页补齐重复订阅及卸载后排队回调保护。
- 票据页的期号订阅移入 Loaded/Unloaded 生命周期；设置页旧更新任务不能覆盖或关闭新提示框。
- 回测提交前检查取消；批量任务保留已经完成的规则结果。
- 视频下载准备、文件读取、AI 返回和保存前检查取消；旧下载收尾只更新自己的界面状态。
- 点位页回测在数据切换及卸载时取消；即使服务忽略取消、返回旧成功或失败，版本检查仍会阻止过期状态回写。
- 年度导出可在生成期间取消，迟到的进度不会覆盖后续阶段或新操作提示。切换期号不改变用户已经发起的导出数据范围；真正卸载时取消未提交的生成任务。已经开始的工作簿写入不被强行中断。
- 年度导出准备阶段异常纳入 UI 错误处理；缺少首期之前历史时明确提示补全数据，避免索引越界。
- 视频搜索的延迟成功和失败均不能替换较新请求的结果，登录后的重试沿用原取消令牌。
- 规则编辑中修改描述、代码或分类会取消旧生成/回测；关闭窗口时取消未完成任务，迟到结果不能覆盖手动编辑。
- LLM 配置中修改地址、密钥、模型或关闭窗口会取消旧请求，防止旧模型列表和测试结果回写。
- B站登录关闭窗口后取消二维码请求和轮询，防止迟到响应继续处理；重复 Loaded 不会启动多个登录循环。

## 回归范围

- 默认套件为 31 组，覆盖算法、命令行、导出范围、账本、数据显示、缓存、取消及页面生命周期。
- 前后通用测量的 11 项完整结果哈希保持一致。最终复核报告在 `tmp/final-optimization-pass/performance.json` 与 `compatibility.json`。
- 矩阵渲染优化阶段的 15 个场景像素、尺寸、行数和控件数全部一致，报告保留在 `tmp/trend-render-pass/`。后续生命周期改动没有修改矩阵渲染代码。
- 数据解析采用旧解析器作为独立参考，覆盖全部内嵌数据、1200 条变体和三种区域设置。
- 异步验证使用本地可控响应，覆盖旧回测成功/失败、卸载取消、旧搜索成功/失败、手动编辑期间生成返回、修改配置期间模型返回，以及旧更新任务遇到新弹窗。
- 页面检查在 STA 线程加载真实 XAML 和主题资源，不显示主窗口，不读取真实凭据。

## 边界

取消是协作式的提交前检查，不回滚已经完成的保存。主窗口通过 Visibility 切换页面，隐藏不等于卸载；隐藏页面接收数据更新的既有行为保留。真实 B站扫码、视频下载和外部 AI 请求依赖账户及网络，没有进行联网端到端验证。

首次创建大矩阵仍需创建全部控件，未承诺与重复刷新相同的速度。本轮没有切换 UI 框架、引入虚拟滚动或升级依赖。优化不代表项目不存在其他可改进点，结论仅覆盖本轮已识别和验证的范围。

```powershell
dotnet build SsqAnalyzer.slnx -c Release
dotnet Verification/bin/Release/net10.0-windows/SsqAnalyzer.Tests.dll
```

验证涉及年度缓存和规则迁移，建议按 Verification/README.md 使用独立输出目录。各阶段的源码备份和测量文件保留在 `tmp/`，不参与主项目编译。
