# 走势图刷新优化记录

日期：2026-09-21。此次优化保留现有预测算法、配色、遗漏值计算和选号规则。

## 改动

`MatrixGrid.Render` 原来以列表引用变化作为完整重建条件。筛选或查询返回新列表时，即便内容相同也会重建所有控件。现在保存上次完整渲染的记录值快照，并比较本次可见记录和实际遗漏矩阵；只有内容一致、期数及 012 排列一致时才复用控件。复制记录值可识别原对象被修改的情况；遗漏矩阵比较覆盖可见窗口之前的历史修正。

遗漏和冷号选项变化仍执行增量显示更新。由于现有增量更新和完整渲染的个别字体样式不同，选项或选号发生变化后遇到新列表时保留完整重建路径，避免改变原有显示效果。完全相同的重复调用跳过无效的显示更新。

`TrendPage` 开启 012 时合并周期、奇偶筛选复位引起的刷新，最终统一渲染一次。

## 测量

Windows、.NET 10.0.9、Release，`DOTNET_TieredCompilation=0`。固定种子 53612，完整历史 150 期，可见 100 期，布局宽度 1200。每项预热后测量 5 次取中位数；每个样本之前执行 GC。计入同步渲染和 WPF 布局，排除窗口显示和 GPU 绘制。内存数值为当前线程累计托管分配，不代表常驻内存或峰值。

| 场景 | 优化前 | 优化后 | 前/后分配量（MiB/次） |
|---|---:|---:|---:|
| 同一列表重复刷新 | 1.05 ms | 0.10 ms | 0.131 / 0.021 |
| 内容相同的新列表 | 206.90 ms | 0.10 ms | 49.207 / 0.022 |
| 实际数据变化重建 | 189.18 ms | 190.16 ms | 49.206 / 49.215 |
| 普通/012 排列切换 | 621.47 ms | 201.28 ms | 49.206 / 49.215 |

收益来自跳过不必要的控件重建。实际数据变化仍需完整重建，耗时基本持平；首次展示同样需要重建。012 切换仍走原有完整渲染流程，其时间差不归因于此轮优化，也不作为稳定加速承诺。
