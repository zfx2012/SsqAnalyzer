# 完整渲染的单元格复用

记录日期：2026-09-22。本轮保持预测算法、矩阵布局、配色、遗漏值、冷号和选号行为不变。

## 改动及边界

完整重建时，普通文字单元格的 Border 和 TextBlock 按原创建顺序复用。重建仍重新计算内容、位置、颜色、边框、字号、字重、标签及可见性；号码球、冷号圆圈和选号逻辑沿用原路径。已被选号操作替换成球形面板的单元格不进入文字复用队列。

复用仅发生在单个 MatrixGrid 内。重建完成后清空多余控件引用，缩小期数或清空数据不会保留上一大窗口的闲置控件。队列和列表的内部数组容量可能保留，但不再引用被淘汰的单元格。

本轮改善数据变化、排列和期数切换时的完整重建。首次创建没有旧单元格可复用，时间基本持平，跟踪列表带来少量额外分配。没有引入虚拟滚动或改变可视树的单元格类型。

## 测量结果

Windows、.NET 10.0.9、Release，`DOTNET_TieredCompilation=0`。使用 `trend-v2-seed-53612` 固定数据，宽度 1200。各项预热后测量 5 次取中位数，包含渲染及同步 WPF 布局；分配量为当前线程累计托管分配，不是常驻或峰值内存。窗口显示和 GPU 绘制不在计时范围内。

| 场景 | 优化前 | 优化后 | 前/后分配（MiB/次） |
|---|---:|---:|---:|
| 100 期实际数据变化重建 | 209.42 ms | 165.66 ms | 49.215 / 16.223 |
| 100 期普通/012 排列切换 | 211.84 ms | 167.71 ms | 49.215 / 33.640 |
| 300→100 期切换 | 228.84 ms | 188.11 ms | 54.101 / 39.363 |
| 100→300 期切换 | 682.71 ms | 647.10 ms | 139.134 / 124.528 |
| 新建 100 期矩阵 | 202.26 ms | 208.02 ms | 46.988 / 47.188 |
| 新建 300 期矩阵 | 661.57 ms | 658.71 ms | 137.264 / 137.726 |

100 期实际数据变化重建在本次测量中耗时减少约 21%，分配减少约 67%；300→100 期耗时减少约 18%。扩大到 300 期仍需创建新增单元格，收益较小。首次创建的时间差不视为加速或稳定退化结论。多轮探索测量存在明显时间波动，表中仅列相同最终测量程序串行运行的前后结果，不能当作用户设备上的响应时间保证。

期数切换在计时前准备起始期数并完成布局，两个方向分开测量。新建矩阵测试的进程、字体已经预热，不代表程序冷启动。

## 验证和复现

15 个场景的原始像素哈希、宽高、行数和控件数前后全部一致，包含原有 13 个显示/交互场景，以及 300 期和缩回 100 期的画面。

新增单元格复用检查：隐藏遗漏后再重建、普通/012 切换、缩小/扩大期数、空数据恢复。每个阶段与全新矩阵的画面逐像素比较，并检查重建确实复用了控件。原缓存失效检查改用行定义判断布局是否重建，因为完整重建现在允许保留单元格对象。
