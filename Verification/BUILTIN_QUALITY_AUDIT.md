# 100 条内置杀号规则质量排查（截至 2026111）

结论：优先优化现有规则的条件依据、重复性和验证方式，暂不继续扩充数量。现有规则能经常达到候选数量要求，但尚不能据此认定有稳定的实际杀号能力。本轮是排查，没有修改规则、启用状态、82%／94% 门槛或用户提交记录。

## 范围与口径

固定当前 100 条定义（73 红、27 蓝），读取本地 3508 期开奖。每条重放 3507 个被预测期，共 350700 次正式 JS 执行。只读取被预测期之前的号码，目标仍为红球剩余 **6—15 个**、蓝球剩余 **1—5 个**；不人为补删号码以达标。

- [100 条逐项成绩和重复对](Fixtures/builtin-quality-2026111.md)：完整规则清单，含触发率、全历史／近500期／最近50次触发成绩、样本跨度、独有排除和错误数量。
- [结构化结果](Fixtures/builtin-quality-2026111.json)：100 条规则统计、版本／数据指纹、组合结果及达到复核条件的重复对。归档仅保留重点重复对，完整运行输出另存所有同球种规则对与逐期输出。
- 本轮“低于随机基线”“独有部分较差”是样本描述，不是统计显著性结论；各类标记可以重叠，不相加作为淘汰总数。
- 近500期是500个实际开奖点；近50次是50次有效触发。单号码正确率 = 正确排除号码数 / 总排除号码数，不等于整期保留中奖号码的比例。

以下均为全部100条固定启用、同球种结果取并集的回顾性重放，不代表用户每一期历史上实际选择了这些规则。

| 红蓝同时达到数量目标 | 223／500（44.6%） | 42／100（42%） |
| 平均保留实际红球 | 2.73／6 | 2.77／6 |
| 6个红球全部保留 | 7期 | 0期 |
| 实际蓝球保留 | 160期 | 35期 |
| 6红+1蓝全部保留 | 5期 | 0期 |
| 同时数量达标且6红+1蓝全部保留 | 1期 | 0期 |

在近500期中，数量同时达标的223期平均只保留2.46个实际红球，蓝球保留63期，完整保留1期。因此重点是提高目标范围内保留开奖号码的能力，不能把达标数量本身当成质量，也不以放宽候选数量替代规则优化。

同等每期候选数量、均匀独立开奖假设下，近500期随机完整保留的期望次数约1.03，实际为5；近100期随机期望约0.21，实际为0。这些稀少事件不能单独证明优势或劣势，尤其规则经过历史挑选。随机期望是各期 `C(剩余红球,6)/C(33,6) × 剩余蓝球/16` 之和，不是“1.03%的命中率”。

真实提交2026111的100条规则版本与当期输出均和此次重放一致：剩16红、6蓝，实际只保留红球31，蓝球05被排除。该记录同时未达到数量目标和完整保留目标。当前这一次真实提交不足以判断长期效果。

## 优先处理的问题

### 1. 历史挑选造成的“50次达标”不能当成验证通过

原50条中31条改过条件，搜索过1263个配置；新增50条从240个最终候选中选出。两部分都使用截至2026109的近期成绩筛选。较早参考段也参与选择，不能再称为独立留出集。详见[条件修订记录](KILL_CONDITION_TUNING.md)和[扩充记录](BUILTIN_100.md)。

在均匀开奖模型下，随机排除一个红球的正确率为27/33≈81.82%，蓝球为15/16=93.75%。82%／94%的现有门槛分别只高0.18、0.25个百分点。对每次排除一个号码的50次触发，41次／47次正确就达标，接近随机期望40.91／46.88次。门槛保留，但其用途只能是历史筛选条件，不能承担证明有效性的职责。

截至2026111已有7条的最近50次触发不达门槛：`B-G-R-001`、`B-G-B-001`、`B-G-R-001-OE`、`B-S-R-001`、`B-S-R-015`、`B-S-B-006`、`B-S-B-011`。其中历史同期冷号杀蓝为93.7282%，不能四舍五入到94%后视为达标。

后续每次修改应保存新版本及修改依据，冻结后再积累实际提交结果；不能看过错误后修改条件，再把同一窗口恢复达标当作改进证明。

### 2. 六条蓝球规则是“杀上期蓝球”的条件子集

`B-S-B-007/019/021`（长缺回补）与 `B-S-B-022/023/024`（紧邻重开）都要求该蓝球在最新一期出现。每期只有一个蓝球，因此它们只要触发，必然输出上期蓝球，与 `B-G-B-002` 相同。这是代码结构上的包含关系，不只是样本相关。

在 `B-G-B-002` 同时启用时，这六条对最终号码并集没有新增贡献。近500期独有排除均为0；基础重号规则的独有贡献在这段样本中也为0，但后者只说明该样本中被其他规则覆盖，不能推断永久冗余。

应将它们作为同一机制的不同触发条件比较：条件是否真的减少错杀、付出多少不触发期、移除后组合是否变化。不要把七个名称作为七份独立证据。首轮去重采用“相同输出／任一触发”超过90%的标准，会漏掉这种触发频率不同的包含关系。

红球 `B-S-R-006`（25期短期重复）与 `B-S-R-008`（20期短期重复）近500期有497期任一触发，其中404期输出相同（81.29%），90期共同错杀。它们也应作为一个机制的参数变体处理。

### 3. 18条较弱规则与16条稀疏规则须分别处理

18条在全历史和近500期的单号码正确率均低于随机基线，且近500期至少触发50次，应优先核查其条件依据。具体列表见下方清单。这不是仅凭本次开奖判定，也不意味着已证明统计上显著更差。

另16条近500期触发少于50次，其最近50次触发均跨越500期以上，最宽1443期。“最近50次达标”可能跨越很多年；暂列样本稀疏，需要披露跨度与最近活跃情况，不能按高正确率优先推荐，也不直接认定无效。

### 4. 描述、时间单位与接口语义需要整理

- `B-G-B-001` 的“同期遗漏≥16”是在历史相同期号样本中计算，约相当于16个年度样本，不是连续16个实际开奖期。近500期单号码正确率93.98%，但499次触发中171次误杀实际蓝球，整期蓝球保留率65.73%。这两个指标应同时显示。
- `B-G-B-002` 的“蓝球通常不会连续重复”、`B-G-R-009` 的“红球通常不等于上期蓝球”本身只是高基准概率下的现象，没有说明为什么选中该号码优于随机排除。同理，历史同期、奇偶期、星期周期拆分需要独立证据，不能只靠图形或名称解释。
- `RuleContext.GetMiss(ball, window)`、`MissMatrixCalculator.GetMissValues(..., window, ...)` 接收 `window`，但实际返回截止当前的累计遗漏，参数不限制窗口。注释却提及“最近window期”，易使后续调参产生误解。应明确累计遗漏和窗口内遗漏的不同语义，再评估规则版本影响；本轮未改变算法。

## 修改顺序及判定原则

1. 先整理上述六条蓝球包含关系、红球重复组，以及遗漏接口／描述语义。保留旧ID与已提交快照，不篡改历史复盘。
2. 逐一复核18条跨窗口偏弱规则，列出“条件为什么应当有效”的可检验依据。无依据的阈值扫描不作为优化成果；不得为恢复50次达标反复试参数。
3. 将16条稀疏规则单列观察，展示实际触发数与时间跨度。对每个规则家族一起评估，避免多个相似版本放大同一类错误。
4. 规则修改后同时检查：目标数量达成比例、实际红球保留数分布、6红完整保留、蓝球保留、红蓝完整保留，以及新版本的真实提交记录。只提高单号码正确率、不改善实际候选集合的修改不算完成目标。

暂不指定“优质规则”名单，也不按一次错误自动删除。当前证据足以安排整改优先级，但不足以承诺优化后稳定预测。
