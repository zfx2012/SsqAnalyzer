# 内置规则扩充至 100 条

保留原 50 条规则及其条件修订，新增 25 条红球、25 条蓝球统计条件规则。新增定义存于 `Resources/builtin-rules-extra.json`，直接加载，不再自动展开变体。ID 使用 B-S-R-001—025、B-S-B-001—025。

## “合理”的范围与成绩口径

新增规则是可解释、可复现的历史统计假设，不是已被证明有效的彩票预测规律。高频、低频等是假设方向不同的候选方法。它们只读取开奖前已有数据，不硬编码期号、日期、号码答案，也不依赖运行时钟或随机值。每条最多杀一个号码，条件不满足时不触发。

本次入选要求是近 **50 次有效触发**红球正确率 ≥82%、蓝球 ≥94%。该成绩参与筛选，属于历史筛选成绩，不是独立验证，也不保证未来继续达标。不同规则可能相关，100 条不代表 100 份独立证据，更不意味着全部同时启用一定更好。

历史样本截至 2026109，共 3506 期；较早参考段截至 2019095。筛选同时记录参考段与全历史成绩，但不强求全部窗口达标。候选资格要求：累计至少 200 次触发，最近 50 次触发落在末尾 500 个实际开奖点之内，最近 30 个开奖点内仍有触发。

## 候选方法

| 方法 | 具体条件与选择方式 |
|---|---|
| 高频 | 窗口内出现次数最多的号码 |
| 低频已出现 | 窗口内至少出现过一次，选择频次最低者，避免未出现号码的固定小号偏置 |
| 降温 | 前后半窗频率下降最大；各半窗按其实际长度归一 |
| 升温 | 前后半窗频率上升最大；奇数窗口也按长度归一，平稳频率不会被误判 |
| 短期重复 | 最近 3 期至少出现 2 次，在这些号码中选整窗频次最高者 |
| 长缺回补 | 最新期出现，且此前连续空缺至少为窗口长度的三分之一，选空缺最长者；上次出现须在窗口内可观测 |
| 短期密集 | 最近 5 期至少出现 2 次，且该频率高于整窗频率，选差值最大者 |
| 中段遗漏 | 当前遗漏介于窗口的四分之一至二分之一（整数向下取整），选择频次最高者 |
| 超均值遗漏 | 窗口内至少出现 2 次，当前遗漏大于“窗口长度 / 出现次数”，选“遗漏 × 频次”最大者；该比值仅为经验尺度 |
| 紧邻重开 | 最新期出现，与上次出现的距离不超过窗口四分之一，选间距最小者 |

全部方法分数相同时取小号，无候选则不输出。统计窗口不足时不触发。

## 筛选与去重

10 个方法 × 红蓝两种球 × 12 个窗口（10、12、15、20、25、30、40、50、60、80、100、120），共 240 个最终候选。初次试算发现奇数半窗长度问题，修正后重跑；最终只采用修正后的结果，初次结果不入库。

达标候选优先采用较早参考段也达标且至少 100 次触发者，再按参考段成绩和累计触发数排序。每个方法、每个球种最多入选 3 条。对最后 500 期，排除双方均未触发的期次后，如输出完全相同的比例超过 90%，则视为高度重复，拒绝与原 50 条或已选新规则重叠的候选。这是输出去重，不是独立性或低相关性证明。

筛选先用独立 C# 实现计算，再用正式 Jint JS 执行器在全部历史点逐期核对每条入选规则。最后使用普通 BacktestEngine 对正式 100 条规则重算 30／50／100／全部四个窗口，最近完成窗口固定为 50 次触发。

## 验证与复现

- 验证程序 `--expand-builtin-rules <ssq_data.txt> <输出目录>` 复现候选和选择流程，仅生成报告与规则定义，不修改用户运行数据。比较基准固定为原始 50 个 ID 的现行条件版本，避免复现时把新增规则与自身比较。
- [完整筛选记录](Fixtures/builtin-100-audit.json) 保存全部 240 个候选、入选项、数据指纹及样本范围。
- 回归检查包含 100 条唯一 ID、原 50 条保留、新增红蓝各 25 条、条件完整历史要求、单号与取值范围、实际开奖隔离、奇数半窗归一、蓝球历史和同分选择，以及既有页面排序、启用和持久化测试。
