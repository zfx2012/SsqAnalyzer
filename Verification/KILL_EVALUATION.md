# 杀号回测评估与前向验证

## 使用

1. 在杀号规则页启用要评估的规则，点击“回测评估”。列表搜索、排序和隐藏不达标仅影响显示。
2. “历史分段与合并评估”对当前已启用规则固定快照，按时间升序执行；默认开发区间占 70%，后 30% 为历史验证区间。两段各至少 30 个开奖点。比例不是准确率门槛。
3. 先看红球、蓝球并集合并结果，再看单规则结果。可以复制或导出当前文本报告，报告含完整规则与数据版本哈希。
4. 实际前向验证须先更新历史，填写紧接历史的目标期号和实际开奖日期，点击“开奖前冻结”。建议日期按周二、四、日推算，不处理节假日停市。只接受未来 10 日内、提前至少一个自然日的目标，并要求最新历史在最近一周内。跨年期号从 001 开始。
5. 每期只能冻结一次，不能覆盖、换规则重选结果。规则、参数、来源历史哈希和当时输出一并存储。应用启动及数据更新时自动结算；“结算 / 查看记录”可主动重试并显示错误。结算不会重新执行规则。
6. 规则详情和列表准确率提示显示当前窗口的新指标。旧统计缺少这些指标时须重新回测；规则代码或参数变化后，旧版本成绩不能作为当前版本的达标依据。

红球 82%、蓝球 94% 固定门槛不变，新增统计比较不自动改变门槛或挑选规则。输出中的“达标规则支持数”只是计数，不是独立证据或命中概率。

## 统计口径

- 号码排除正确率：所有被杀号码中未开出号码的比例，按杀号数量加权。
- 触发率：有杀号输出的期数 / 成功执行期数；平均杀号数：总杀号数 / 触发期数。
- 整期错杀率：至少错杀一个开奖号的期数 / 触发期数；完整保留率是其补数。没有触发时为空值。
- 最长连续错杀：按检查期连续计算，未触发、完整保留或执行失败会中断连续段。缺失历史不会被补造为样本，分段报告显示同年缺失期号数量。
- 失败单列，不能当作未触发或成功。合并按同一期各规则号码并集计算；任一参与规则失败，则该球种整期失败。有失败时不提供优势评价。
- 随机排除的理论正确率为红球 27/33 ≈ 81.82%，蓝球 15/16 = 93.75%。固定门槛只略高于随机基准，达标本身不足以证明预测价值。
- 条件随机对照保留观察到的每期触发与杀号数量，按超几何分布模拟 2000 次，避免将同期开奖的号码当作独立样本。尾部概率采用加一修正，最小约 1/2001。这不是对完整自适应选规则流程的精确显著性检验。
- 历史正确率的 95% 区间使用按开奖期的循环移动块重采样 1000 次，块长为期数立方根向上取整。它描述历史估计的不确定性，不是未来开奖的预测区间；小样本、全对样本、结构变化时可能偏乐观。触发不足 30 次时不报告区间或比较概率。
- Bonferroni 调整范围：普通窗口回测为当前规则数 × 4 窗口；历史分段为（规则数 + 两个合并结果）× 2 区间；前向汇总为（该版本规则数 + 两个合并结果）× 已记录版本数。它不覆盖未记录的历史尝试、多次查看或反复调参。

历史验证是回顾性分析。如果曾经用这段数据改过规则，即使重新划分也不是真正未见数据。前向数据需要等待后续实际开奖积累，本次实现不产生未来成绩、不证明存在可预测优势。

## 保存与一致性

普通回测独立保存 30/50/100 次触发及全部窗口，另存风险指标、规则指纹、数据指纹。计算采用规则和历史快照；期间规则变更则拒绝保存过期结果。

前向账本为程序数据目录中的 `kill_forward_validation.json`，以独占文件锁和临时文件替换写入，分别保存冻结和结算哈希链。通过公开操作只能追加，重复结算幂等；日期、来源历史、既有开奖结果发生变化或哈希校验失败时拒绝覆盖。不同规则集合版本分别汇总，尚未开奖记录不纳入成绩。该文件不提交 Git。

这是本地审计记录。系统时钟、本地文件和本地开奖数据并非第三方可信时间戳；哈希链能够发现意外改动，但不能阻止有权限的人重新编写整个文件。

规则参数现在作为 JSON 注入 `ctx.params`；规则执行禁用 `Date` 与 `Math.random`，避免依赖运行时钟和随机值。历史日期应通过历史上下文访问。

## 验证

`dotnet build Verification/SsqAnalyzer.PositionVerification.csproj -c Release -o tmp/kill-evaluation/final`

`dotnet tmp/kill-evaluation/final/SsqAnalyzer.Tests.dll --evaluation-check`

`dotnet tmp/kill-evaluation/final/SsqAnalyzer.Tests.dll --page-check`

默认运行全部验证组。新增检查包括指标分母、超几何边界、重采样可复现、参数与时钟限制、逐期历史边界、开发/验证分离、合并去重与失败策略、冻结截止、重复记录、结算幂等、后续规则修改、开奖结果修改保护、哈希损坏拒绝，以及真实 WPF 窗口后台评估与渲染。原有排序、勾选、窗口统计和固定门槛回归保留。

方法参考：[时间序列交叉验证](https://scikit-learn.org/stable/modules/cross_validation.html)、[NIST Bonferroni 方法](https://www.itl.nist.gov/div898/handbook/prc/section4/prc463.htm)、[NIST 超几何分布](https://itl.nist.gov/div898/software/dataplot/refman2/ch8/hypcdf.pdf)。
